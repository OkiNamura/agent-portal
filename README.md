# Agent Portal

Локальная «коробка»: оркестратор + агенты + артефакты. Запускается одной командой, живёт на твоей машине, позже переносится на сервер как есть.

```
задание → декомпозиция → спеки → макет → код → проверка и правки → сводка
             ↑гейт         ↑гейт   ↑гейт                             ↑гейт
```

Между гейтами работают агенты, на гейте — решаешь ты: принять или вернуть на доработку с комментарием.

## Быстрый старт

```bat
start.cmd
```

или

```bat
node server.mjs
```

Открой **http://127.0.0.1:7777**

Без ключа OpenRouter портал поднимается в **MOCK-режиме**: весь каскад проходит на заглушках, без трат и без сети. Это чтобы посмотреть механику.

## Живой режим

1. Скопируй `.env.example` → `.env`
2. Впиши ключ: `OPENROUTER_API_KEY=sk-or-v1-...`
3. Перезапусти сервер

Бейдж в шапке сменится на `LIVE · OpenRouter`. Ключ читается только сервером, в браузер не попадает.

## Что внутри

| Файл | Зачем |
|---|---|
| `server.mjs` | HTTP-сервер, API, SSE-стрим событий |
| `lib/engine.mjs` | конвейер: стадии, гейты, цикл правок |
| `lib/prompts.mjs` | промты стадий (что именно спрашиваем у агента) |
| `lib/llm.mjs` | вызов модели + разбор JSON с повтором |
| `lib/mock.mjs` | заглушка для MOCK-режима |
| `config/agents.json` | роли, модели, системные промты |
| `config/pipeline.json` | стадии, гейты, лимит правок, команда тестов |
| `runs/<id>/` | состояние прогона, события, артефакты |
| `public/` | интерфейс, без сборки и без зависимостей |

## Как это работает

**Стадии** (`config/pipeline.json`):

1. `plan` — оркестратор режет задачу на 2–6 блоков с критериями приёмки → **гейт**
2. `spec` — архитектор пишет спеку на каждый блок → **гейт**
3. `design` — дизайнер описывает экран/поведение
4. `build` — инженер пишет файлы под спеку
5. `verify` — тестировщик ищет дефекты; если нашёл — инженер правит, до `maxFixRounds` кругов
6. `report` — ревизор собирает сводку → **гейт**

**Артефакты** пишутся на диск в `runs/<id>/artifacts/`: `plan.md`, `blocks/b1/spec.md`, `blocks/b1/test-1.md`, `work/src/...`, `summary.md`. Всё, что видно в интерфейсе, лежит файлами — можно читать в редакторе и коммитить в git.

**Команда тестов** (необязательно): в `config/pipeline.json` поле `testCommand`, например `node --test`. Она выполняется в `runs/<id>/artifacts/work/`, её вывод уходит тестировщику как факт, а не как мнение.

## Гейты и «вернуть на доработку»

На гейте есть комментарий. Если нажать «Вернуть на доработку» — стадия перезапустится с твоим замечанием, агент его увидит. Это же работает как «поправь формулировку»: не надо перезапускать весь прогон.

## Интерфейс: 4 колонки

1. **Меню** (иконки): Проекты · Агенты · Статистика.
2. **Список раздела**: проекты (с удалением) или агенты; «+» создаёт новый.
3. **Рабочая область**: у проекта — вкладки «Ход», «Макет», «Файлы»; у агента — карточка с моделью и промтом; у статистики — расход по моделям/проектам/дням.
4. **Правая колонка**: Пайплайн, Прогоны, Текущие задачи, Логи — всё сворачивается.

Удаление защищено: агента, занятого в пайплайне, удалить нельзя; проект с активными прогонами — тоже.

Прогон можно остановить кнопкой «■ Остановить» в шапке вкладок (текущий вызов модели доиграет, дальше стадии не пойдут).

## Ассистент

Страница «Ассистент» отвечает на вопросы по порталу: где остановился проект, были ли ошибки, сколько потрачено. Перед вопросом собирается срез: проекты, версии, статусы, гейты, блоки, ошибки, расход — и уходит в модель вместе с вопросом. Отвечает только по данным, выдумывать не должен. В MOCK-режиме показывает этот срез без вызова модели.

Стоимость вопроса — доли цента (deepseek-v3.2, ~2–4k токенов контекста).

## Доработка готового прогона

На готовом прогоне появляется поле «Доработка»: пишешь изменение («добавь кнопку =»), и создаётся новый прогон, в который перенесён весь код предыдущего. Агенты правят существующий проект, а не начинают с нуля.

Замер на калькуляторе:

| | с нуля | доработка |
|---|---|---|
| вызовов модели | 28 | 14 |
| стоимость | $0.0398 | $0.0217 |
| время | ~13 мин | 4.7 мин |
| кругов правок | 3 блока × 2 | 0 |

В `state.json` доработка помнит `baseId` — видно, откуда она выросла.

## Проверки процесса

`scripts/probe.mjs` гоняет портал по сценариям (старт, отказ без комментария, повторное подтверждение, отмена, параллельный прогон, доработка, SSE, битая модель) на отдельном MOCK-сервере:

```bat
set PORT=7778
set RUNS_DIR=%TEMP%\portal-probe
node server.mjs --mock
node scripts/probe.mjs
```

## Ограничения v1

- Стадии идут последовательно: блоки не выполняются параллельно (осознанно — они пишут в один каталог, конфликты дороже скорости).
- Гейт видит все блоки сразу: подтверждаешь стадию целиком, не отдельный блок.
- Нет стриминга токенов: в логе видно стадии и вызовы, не посимвольный вывод.
- Прогон, прерванный перезапуском сервера, помечается `прерван`; его можно продолжить кнопкой в интерфейсе (стадия перезапустится).
- Команда тестов запускается локально от твоего пользователя — это доверенный код проекта, не песочница.

## Что показал первый живой прогон

Первый прогон «калькулятора» на DeepSeek: **0 из 4 блоков** прошли проверку. Причины были не в модели, а в конвейере:

1. **Блоки не видели друг друга.** Каждый блок писал в свою папку `src/b1/`, `src/b2/`, и получалось четыре несовместимых куска вместо одного проекта. Исправлено: у прогона теперь общий `workspace`, инженер получает весь проект и дополняет его.
2. **Тестировщик придирался к стилю** («символ − вместо -»), и это блокировало приёмку. Исправлено: дефект = нарушение конкретного критерия; стиль и неоднозначности не считаются дефектами; добавлена таблица «критерий → выполнен».
3. **HTTP-запрос подтверждения висел** всё время следующей стадии (минуты) и ронял клиента по таймауту. Исправлено: подтверждение отвечает сразу, работа продолжается в фоне.

Второй прогон: **4 из 4** блоков, 28 вызовов, ~13 минут, **$0.04**.

## Тесты кодом, а не глазами

В `config/pipeline.json` есть `testCommand` — например `node --test` или `npm test`. Он выполняется в `artifacts/work/` перед проверкой, и её результат уходит тестировщику как факт. Пока поле пустое, тестировщик судит по чтению кода — это слабее.


## Позже на сервер

Ничего переписывать не нужно: тот же `node server.mjs`, порт из `.env`, сверху nginx. Доступ по сети закрывается токеном — в v1 предполагается localhost.

## Git

Репозиторий: **git@github.com:OkiNamura/agent-portal.git** (ветка `main`).

В `.gitignore` уходят секреты и данные: `.env`, `config/keys.json`, `runs/`, `studio/`, `output/`, `projects.json`, `mailbox.json`, `.tools/`.

Перед коммитом полезно прогнать проверку на секреты:

```bat
node scripts/check-secrets.mjs
```

Он ищет ключи OpenRouter/OpenAI/Anthropic/Telegram в файлах и возвращает ошибку, если что-то нашёл. Дополнительно GitHub сам блокирует пуш с секретом (push protection) — так и был пойман случай с `config/keys.json`.

Пуш:

```bat
git.cmd push
```

`git.cmd` — обёртка над портативным git: подставляет SSH-ключ из `.tools/ssh2` и вызывает `.tools/git/cmd/git.exe`. Так работает в том числе из песочницы, где обычный git не может запустить свой `sh`.
