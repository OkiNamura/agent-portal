# 00. Обзор

## Что это за продукт

Однопользовательская текстовая RPG в браузере. Ведущий — языковая модель: она пишет сцену
от второго лица, а игрок управляет одним персонажем свободным текстом. Всё, что поддаётся
проверке (деньги, предметы, раны, задачи, отношения, время, место), хранится не в прозе,
а в типизированном JSON-состоянии. Проза — для игрока, состояние — для правды.

Эталон, с которого снято ТЗ, — проект **Omika** (в репозитории `PRG`). Ниже он называется PRG.

## Для кого

1. **Разработчик-исполнитель.** Ему нужен воспроизводимый набор контрактов: какие данные
   ходят между слоями, что считается корректным ходом, какие проверки обязательны.
2. **Мультиагентный конвейер.** Блоки 1–15 в `02-specs.md` нарезаны так, чтобы их можно было
   раздавать параллельно: у каждого блока свои входы, выходы и проверяемые критерии.
3. **Владелец продукта.** Ему нужен ответ на вопрос «что именно мы обещаем игроку и чем это
   отличается от чата с моделью», без деталей реализации.

## Чем отличается от обычного чата с моделью

| Обычный чат | Эта игра |
|---|---|
| История растёт, пока не кончится окно | В контекст идут последние 30 ходов плюс скользящий конспект с лимитом 6000 знаков (в PRG конспект пересказывает всю историю, включая эти 30 ходов) |
| Модель «помнит» цифры в тексте | Цифры живут в состоянии, модель предлагает изменения отдельным JSON, движок их валидирует и применяет |
| Модель отвечает как угодно | Критик проверяет границу хода: нет вопросов игроку, нет «тебе решать», есть блок изменений, объём в норме |
| Нельзя отменить ответ | Снимок после каждого хода: перегенерация, правка реплики, ветки-варианты, откат |
| Стоимость непонятна | На каждый ход считаются токены, попадание в кэш префикса и деньги, отдельно по агентам |
| Один промт | Четыре неизменных блока (ядро, мир, тон, герой) + история + конспект + состояние, в фиксированном порядке |

Ключевое архитектурное решение: **порядок контекста фиксирован от самого стабильного
к самому изменчивому**. Стабильный префикс попадает в кэш провайдера, поэтому ход на десятки
тысяч токенов стоит на порядок меньше, чем без кэша. Это не оптимизация «на потом», а причина,
по которой история отдаётся сообщениями, а состояние стоит в хвосте.

## Границы

- Один игрок, один персонаж, один сервер, файловое хранилище. Аккаунтов, мультиплеера и биллинга нет.
- Сервер слушает только `127.0.0.1`. Ключ провайдера читается сервером и в браузер не попадает.
- Язык интерфейса и прозы — русский; это влияет на оценку токенов (3,2 символа на токен).
- Иллюстрации, ASCII-карты и статистика — отдельный контур; без них игра остаётся играбельной.

## Глоссарий

| Термин | Значение |
|---|---|
| **Кампания** | Одна сохранённая игра: тексты (ядро, мир, тон, герой), состояние, конспект, снимки ходов, свои настройки агентов, счётчики расхода. Файл `data/campaigns/<id>.json`. |
| **Ход** | Один цикл «ввод игрока → контекст → ответ ведущего → изменения → запись в лог → снимок». Нумеруется с 1, хранится в `state.turn`. |
| **Состояние** | Типизированный JSON: время, место, погода, здоровье, раны, эффекты, деньги, предметы с местом нахождения, пати, знакомые, задачи, обещания, крючки, фракции, места, архив, бестиарий, скрытые факты, флаги, лог. Единственный источник правды о цифрах. |
| **Дельта** | Блок изменений состояния за ход. Модель предлагает, движок проверяет: непрошедшее изменение отбрасывается, ход продолжается. |
| **Конспект** | Память о том, что старше окна последних ходов. В PRG сосуществуют две формы: (а) append-only арки, где закрытая арка не переписывается; (б) скользящий пересказ `summary`, который агент-конспектировщик переписывает каждый ход (лимит 6000 знаков). На практике в PRG работает (б), арки пусты. |
| **Критик** | Детерминированная проверка ответа ведущего: пустая проза, отсутствие дельты, перебор объёма, вопросы игроку, подталкивание к решению, число скрытых фактов, действие с предметом без изменений. Модель в критике не участвует. |
| **Снимок** | Копия состояния и конспекта после хода N (`TurnSnapshot`). База для перегенерации, правки реплики и вариантов. Плюс `initial` — состояние до первого хода. |
| **Вариант** | Сохранённый прежний ответ на ход вместе с его состоянием. Переключение варианта меняет состояние, а не только текст. |
| **Арка** | Единица конспекта: заголовок + тело. Открытая арка пополняется строками, закрытая замораживается. |
| **Библия кампании** | Четыре неизменных текстовых блока: ядро (общее для всех игр), мир, тон, герой. После старта не меняется. |
| **Агент** | Именованная роль со своими моделью, температурой, лимитом токенов и промтом. Роли: `gm`, `state`, `summarizer`, четыре иллюстратора. |
| **Сегмент** | Именованная часть собранного контекста с длиной, оценкой токенов и хешем. По хешам считается попадание в кэш. |
| **Кэш-префикс** | Число токенов в начале запроса, совпавших с предыдущим ходом побайтово. Учитывается в стоимости хода. |

## Что в PRG готово и что нет

Готово и проверено кодом: состояние и его нормализация, применение дельты с валидацией,
сборка контекста с сегментами и расчётом кэш-префикса, цикл хода, клиент OpenRouter со
структурным выводом и стримом, сохранение кампании и снимки, откаты/правки/варианты,
семь агентов с настройками, детерминированный критик, HTTP API, веб-клиент на шесть экранов,
иллюстрации, две детерминированные карты, статистика расхода.

Отсутствует или сделано наполовину (подробно — в `01-architecture.md`, раздел «Честный статус»,
и в каждом блоке `02-specs.md`): append-only конспект не используется в рабочем цикле;
повтор хода по провалу критика не реализован; нет блокировки сессии и таймаутов вызова модели;
поля `everyMessages` и настройки иллюстраторов кампании не применяются; схема структурного
вывода уже, чем поддерживаемая дельта; цены считаются по одной модели, а не по модели каждого
агента. Перечисленное в ТЗ либо нормировано как обязательное (с пометкой «сверх PRG»), либо
явно исключено из объёма.
